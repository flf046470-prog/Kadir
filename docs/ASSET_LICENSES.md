# Asset licences

§32 requires that every shipped asset has known commercial-use licensing, and
that assets of uncertain licence are not used.

**The short version: this product ships no third-party artwork.** Every visual
asset is either generated by code in this repository or is an open-licensed font
served by Google Fonts. There is no stock photography, no purchased icon set, no
3D model, no audio, and no music.

That is a deliberate position rather than an accident. An asset with an unclear
licence is a legal problem that surfaces years later, usually at the point of
sale, and the cheapest time to not have one is now.

`next/font/google` downloads the font files at build time and **self-hosts**
them, so no request goes to Google from a member's browser — which is a privacy
property as much as a licensing one.

Emoji are worth a note: the gift catalogue stores code points, not images, so
what a member sees is their own platform's emoji font. Nothing is embedded and
no vendor's artwork ships.

## Demo profile photos, specifically

`seed:demo` generates a gradient with an abstract head-and-shoulders silhouette
for each demo member. **No real person's photograph is used anywhere**, in the
app or in any store listing, and that is not only about licensing:

- Putting a real face on a dating app's store listing implies that person is a
  member of a dating service. Even with a licence permitting commercial use,
  that is a misrepresentation about a real human being.
- A stock photo licence that permits commercial use often *excludes* exactly this
  — "sensitive" uses such as dating, health and politics are a standard
  carve-out. A licence check that stopped at "commercial use: yes" would miss it.

The earlier version was a plain gradient and read as a broken image, which is
its own store-review risk; the silhouette makes it read as an intentional
abstract avatar. When the product has real members who have consented, re-shoot.

## When the VR work starts

This register currently has nothing in it that a VR client needs — no
environments, avatars, animations, sounds or music, because none exist.

That is where §32 will actually bite, since those are exactly the categories
where people reach for an asset store. **Every acquired asset needs a row here**
with its source, licence, commercial-use status and attribution requirement,
recorded when it is acquired rather than reconstructed later. Two specifics
worth stating in advance:

- A Unity Asset Store licence is per-seat and generally does not permit
  redistributing source assets; check whether a shipped build counts as
  redistribution for the asset in question.
- "Free" and "royalty-free" are not the same as "usable in a commercial product
  without attribution", and CC-BY requires attribution *in the product*, which
  means a credits screen has to exist before a CC-BY asset can be used.

## Checking this

There is no automated licence check, because there is nothing to check: the
register above is short precisely because everything is generated. If a
third-party asset is ever added, this file is the thing that must be updated in
the same commit — and at that point an automated inventory becomes worth
writing.
